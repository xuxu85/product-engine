# PROJECT PROGRESS

## Purpose

This is the canonical progress model for PRODUCT ENGINE.

The progress percentage measures **actual progress toward the business outcome**, not the amount of code, research, files, API calls, or infrastructure created.

## Final outcome

`PRODUCT → PROTOTYPE → PILOT → FIRST REAL SALE → REPEAT PURCHASE → PROFITABLE SCALE`

## Progress rules

1. Every project-chat response in PRODUCT ENGINE should end with a visible 0–100% progress bar.
2. The bar represents progress toward the full project outcome, with `100%` meaning a commercially validated product has reached repeat purchase and profitable scale.
3. Progress moves primarily when a decision gate is actually passed, not when technical work merely increases.
4. Technical infrastructure can increase progress only insofar as it closes a real bottleneck required by the next business gate.
5. Synthetic tests prove architecture readiness only; they do not count as consumer demand evidence or sales.
6. A failed or invalidated gate can reduce the percentage when the project has materially lost validated ground.
7. The percentage must remain conservative: do not inflate progress to create a feeling of momentum.
8. The bar should always show both the visual scale and the numeric percentage.
